# Setup

## 1. Install

Requires Python 3.11+, [uv](https://docs.astral.sh/uv/) and Git.

```bash
git clone https://github.com/bolorbud-gif/business-analytics-portfolio.git
cd business-analytics-portfolio
uv sync
```

`uv sync` creates `.venv/` with the exact versions in `uv.lock` and installs this project, so
`from src.data_pipeline.pipeline import run_pipeline` works from scripts, tests and notebooks.

## 2. Try it with the synthetic sample (no access needed)

```bash
uv run python scripts/run_pipeline.py --sample
uv run pytest
```

This builds `data/processed/rare_earth_sample.db` from `data/sample/` and writes
[`quality_report_sample.md`](quality_report_sample.md). The sample has the same columns as the
real files but random values. It includes planted bad records (a duplicate, a negative value,
a wrong unit, a header/cell swap) so you can see each quality rule work.

## 3. Restricted data: what is and isn't in this repository

The real source files are **not committed**. They come from third-party providers whose terms
may restrict redistribution, and raw extracts don't belong in version control. The repository
holds only what a reviewer needs to check the work:

| Committed (safe to review) | Never committed (git-ignored) |
|---|---|
| Code (`src/`, `scripts/`, `tests/`) | Real source files: `data/raw/*` |
| Schema: [`schema.sql`](schema.sql), [`ERD.md`](ERD.md), [`data_dictionary.md`](data_dictionary.md) | The databases: `data/processed/*` |
| Synthetic sample: `data/sample/` (generated by `scripts/make_sample_data.py`) | Rejected rows: `data/interim/*` (they contain raw records) |
| Quality reports with aggregate counts only: [`quality_report.md`](quality_report.md) | Logs: `logs/` |
| The dashboard's results snapshot: `data/published/`. Results **derived** from the real data, including country-level figures (imports, power data, predictions), published by the author's decision so the dashboard shows real findings from a clean clone ([deployment.md](deployment.md)) | Secrets: `config/secrets.yaml`, `*.key`, `*.pem` |

Check before committing that nothing restricted is staged:

```bash
git status --short --ignored data/
```

Files in `data/raw/`, `data/interim/` and `data/processed/` should be listed under `!!` (ignored), never
`A` or `M`. Only `data/published/` and `data/sample/` are tracked.

## Supplying the real data

For authorized users who have their own access to the source data:

1. Get the two files from the data owner (the project author) or download them yourself under
   your own licence with the provider:
   - **`data1.xlsx`:** China's trade in HS 284690 (rare-earth compounds) by partner,
     2020–2025, exports and imports, in the WITS "By-HS6Product" layout.
   - **`data2.xlsx`:** yearly electricity generation by country and source, 2020–2025, in Ember's
     layout.
2. Save them as `data/raw/data1.xlsx` and `data/raw/data2.xlsx`, with exactly these names. To use
   other names, change `pipeline.sources` in [`config/app_config.yaml`](../config/app_config.yaml).
3. Check the columns match the source column names in the [data dictionary](data_dictionary.md).
   The pipeline stops with a "table structure is invalid" message if one is missing.
4. Build the database:

   ```bash
   uv run python scripts/run_pipeline.py
   ```

5. Read [`quality_report.md`](quality_report.md). If any rows were rejected, they're in
   `data/interim/rejected_<table>.csv` with the reason. Fix them at the source if needed, then
   run again.

## Querying the database yourself

Open it with the project's helper, not a bare `sqlite3.connect()`. SQLite turns foreign keys
off for every new connection unless told otherwise, and the helper turns them on:

```python
from src.data_pipeline.load import connect
import pandas as pd

con = connect("data/processed/rare_earth.db")   # from a notebook: "../data/processed/rare_earth.db"
pd.read_sql("SELECT * FROM trade_wind_wide WHERE year = 2024", con)
```

Money is stored as whole US dollars in `trade_flows.trade_value_usd` (an exact integer). The
views show `trade_value_kusd` (thousand USD) for convenience.

## Re-running and resetting

- **Refresh:** run the same command again. Each table is replaced in one transaction, so
  nothing is duplicated, and the quality report's *Re-runnability check* shows the row count
  and checksum before and after.
- **Rebuild:** add `--rebuild` to drop and recreate the tables. Use this after a schema change;
  the pipeline asks for it when the database layout is outdated.
- **Switch to PostgreSQL:** change `database.url` in
  [`config/database.yaml`](../config/database.yaml) and add a driver, for example `uv add "psycopg[binary]"`.
